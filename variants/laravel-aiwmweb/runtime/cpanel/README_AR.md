# تثبيت Laravel AIWMWeb على cPanel

هذه حزمة مرشحة؛ لا تُعتبر إصدارًا معتمدًا قبل نجاح فحوصات نفس SHA وتجربة الاستضافة. لم يتم نشرها على الإنتاج. الذكاء الاصطناعي وOllama والجدولة معطّلون مبدئيًا.

## التثبيت الجديد

1. اختر PHP 8.3 أو أحدث، وفعّل pdo_mysql وmbstring وopenssl وfileinfo وtokenizer وctype وXML/DOM وcurl وsession وzip وGD. أنشئ قاعدة MySQL 8 أو MariaDB 10.11+ فارغة ومستخدمًا لها بصلاحيات الترحيل. لا تحتاج Composer أو Node على الاستضافة.
2. ارفع ZIP وفكّه داخل HOME خارج public_html. مجلد app خاص؛ اجعل جذر الدومين AIMWWeb/public فقط. لا تعرض مجلد app أو جذر الحزمة. إذا تعذّر تعديل جذر الدومين فتوقف لحين التحقق من حل متوافق مع استضافتك.
3. فعّل HTTPS ثم Directory Privacy من cPanel على مجلد public قبل فتح المثبّت. الحزمة لا تحتوي كلمة سر تثبيت مشتركة.
4. افتح /install.php وأدخل رابط الموقع وبيانات قاعدة البيانات والمدير الأول. كلمة المرور لا تقل عن 12 حرفًا. يتحقق المثبّت من المتطلبات وسلامة الملفات، ويُنشئ APP_KEY مرة واحدة فقط وبيئة خاصة، ثم يرحّل القاعدة ويُنشئ صلاحيات المالك ويختبر بيانات الدخول ويقفل نفسه.
5. بعد تسجيل الدخول أزل Directory Privacy. تأكد أن /install.php و/setup يرجعان 404، وأن ملفات .env وvendor والسجلات والنسخ الاحتياطية غير متاحة من الويب. اختبر جلسة HTTPS وخصائص Secure وHttpOnly.
6. جرّب موقع WordPress تجريبيًا: المصادقة، قراءة المحتوى، تحريره، المسودة، الموافقة ثم التنفيذ والإيصال. لا تستخدم موقع إنتاج أثناء التجربة الأولى.

## تشغيل آمن

الجلسات والكاش والطوابير تستخدم قاعدة البيانات، دون افتراض Redis. لا يوجد Supervisor أو Horizon أو عامل دائم. تتطلب الجدولة تحقق دعم الاستضافة من PHP CLI وflock وtimeout وpcntl والذاكرة وحدود العمليات وقفل قاعدة البيانات.

استخدم Cron واحدًا فقط يشغّل cron.sh، وحدد AIMW_APP_ROOT للمجلد الخاص وAIMW_PHP_BIN لمسار PHP من لوحة الاستضافة. القفل flock غير حاجب؛ المهلة الخارجية 110 ثوانٍ ثم 5 ثوانٍ للقتل، مهلة العامل 45 ثانية، ومهلة المزوّد بحد أقصى 30 ثانية. العامل يعالج وظيفة طابور واحدة ومهمة AI واحدة كحد أقصى لكل تشغيل، والذاكرة 192 MiB للعملية و128 MiB للعامل.

لا تضبط CPANEL_PREFLIGHT_PASSED وCPANEL_CRON_ENABLED إلى true إلا بعد اختبار تشغيلين متزامنين والتحقق من عدم التداخل ومن حدود الاستضافة. يظل CPANEL_AI_ENABLED=false حتى إعداد المزوّد والنموذج والميزانية والتحقق منهما. لا تشغّل أو تفحص Ollama قبل معالجة مسؤول البنية التحتية لمشكلة الخادم والتحقق من سلامته.

الحدود الافتراضية: 100 اتصال يوميًا، وحجز 100000 توكن يوميًا، وميزانية تقديرية دولار واحد يوميًا مع حجز 0.10 دولار لكل اتصال. هذه حدود قبول تقديرية وليست ضمانًا لفاتورة المزوّد. النتائج المنتهية تُحفظ ولا يعاد توليدها. الطلب الغامض أو القفل المنتهي يتحول إلى needs_reconciliation ويوقف التنفيذ حتى المراجعة؛ لا تُعد تشغيله تلقائيًا.

## الترقية والتراجع

1. تحقق من SHA-256 وMANIFEST ومن نجاح CI لنفس SHA وتوافق قاعدة البيانات والمساحة المتاحة.
2. ضع التطبيق في الصيانة وأوقف Cron. احفظ نسخة كاملة من التطبيق و.env وAPP_KEY والملفات والاعتماديات وstorage، وصدّر قاعدة البيانات من cPanel أو phpMyAdmin. اختبر استعادة القاعدة في قاعدة مؤقتة قبل أي ترقية.
3. فك المرشح في مجلد منفصل. انقل إليه .env الأصلي وstorage وقفل التثبيت والرفع والاعتمادات، دون إعادة إنشاء APP_KEY أو الكتابة فوق التطبيق القديم.
4. تحقق من ملفات الترحيل ثم شغّل artisan migrate --force من Terminal بعد التحقق من النسخة الاحتياطية. لا تستخدم migrate:fresh أو reset أو seed أو تفريغ الطوابير. غيّر جذر الدومين بعد نجاح التحقق فقط.
5. اختبر الدخول وعزل المستأجرين والمواقع والرفع وحالة AI المعطّل وقراءة WordPress والموافقات قبل إعادة الجدولة.
6. إذا فشل التحقق، أوقف الجدولة وأعد جذر الدومين للتطبيق القديم. إذا احتاج مخطط القاعدة إلى استرجاع، استعد النسخة التي اختُبرت تحت وضع الصيانة. لا توجد آلية تراجع تلقائي لقاعدة البيانات ولا يُدّعى وجودها.

احتفظ بسجل خاص يضم SHA ومسارات النسخ وبصماتها ونتائج التحقق. تفاصيل HTTPS وDirectory Privacy وسياسة العمليات في cPanel لا تُعد متحققة بمجرد نجاح اختبار Linux محلي. راجع README_EN.md للتفاصيل والأوامر.
