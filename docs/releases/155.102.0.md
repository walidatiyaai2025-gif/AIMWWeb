# AI WordPress Manager v155.102.0

## Scope

Phase 10 email delivery reliability (`EML-009`) foundation and active delivery worker.

## Added

- Durable `EmailOutboxMessage` persistence with immutable message/recipient snapshots.
- Explicit `OwnerUserId`, site/account delivery scope, optional `SiteId`/`ScheduleId`, `IdempotencyKey`, and `CorrelationId`.
- Owner-scoped unique idempotency enforcement.
- Conditional database claim operation so competing workers cannot intentionally claim the same queued message.
- Exponential retry/backoff with bounded attempts.
- Restart recovery for stale `Sending` claims.
- Sanitized `EmailDeliveryAttempt` history without SMTP passwords or provider payload secrets.
- SQLite compatibility initialization for existing installations, including safe `Scope` upgrade.
- `IEmailOutbox` application contract and scoped persistence implementation.
- Active `EmailOutboxWorker`, gated by `Database:SetupComplete`.
- Explicit background owner resolution; the worker never uses the interactive `CurrentUserContext`.
- SMTP profile resolution for site profiles and inherited account profiles.
- Safe failure categorization for configuration, network, timeout, TLS, and SMTP failures.
- Regression tests for idempotent enqueue, exclusive claim, retry/backoff, sent state, stale-claim recovery, and tenant ownership rejection.

## Reliability notes

- Application shutdown during an active send intentionally leaves the message in `Sending`; the stale-claim recovery path returns it to retry after restart.
- A site-scoped message keeps an explicit `Site` scope even if the site is later removed. It will fail safely rather than silently switching to the account sender.
- Message bodies and recipients are snapshotted before delivery so retries send the same content to the same recipient set.
- SMTP credentials are resolved only when a worker processes a claimed message and remain protected at rest.

## Validation status

`EML-009` remains `in_progress` until a clean Release build/test run and real SMTP runtime delivery/retry verification are completed on the target Windows environment.
