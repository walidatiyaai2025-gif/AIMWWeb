# 155.102.0 — Account lockout hardening and outbox state consistency

## IDN-010 — Account lockout and failed sign-in tracking

- Retains the existing five-failed-attempt threshold and fifteen-minute lockout window.
- Adds an explicit domain lockout-state check.
- Clears expired lockout state before counting a subsequent failed attempt, so one failure after expiry starts a new attempt window instead of immediately extending the old lock.
- Preserves successful-login reset behavior and existing login audit records.
- Adds automated coverage for active lockout, exact expiry, post-expiry failures, and successful recovery.

## CI blocker fixed — Email outbox tracked-state consistency

The outbox claim path uses EF Core `ExecuteUpdateAsync`, which updates the database without synchronizing already tracked entities in the current `DbContext`. A stale tracked `Queued` entity could therefore be reused after the row had moved to `Sending`, breaking sent/failed/stale-claim transitions.

- Detaches only tracked `EmailOutboxMessage` entries before claim/recovery reads that must observe database state.
- Detaches the specific message before validating a claim token for sent/failed transitions.
- Preserves current tenant scope fields, idempotency, retry, delivery-attempt, and restart-safe worker behavior.

No database schema change is required.
