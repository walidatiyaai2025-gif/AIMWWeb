# 155.102.0 — Account lockout hardening

## IDN-010

Completed the account lockout and failed sign-in tracking behavior for local application users.

### Changes
- Keeps the existing five-failed-attempt threshold and fifteen-minute lockout window.
- Adds an explicit domain-level lockout-state check.
- Resets an expired lockout before counting a new failed attempt, preventing one failure after expiry from immediately extending the previous lock.
- Preserves successful-login behavior that clears failed-attempt state and records the last successful login timestamp.
- Adds automated coverage for active lockout, exact expiry, post-expiry failures, and successful recovery.

### Security notes
- Password hashes and authentication secrets are unchanged and are not logged.
- Existing login audit records continue to capture failed, locked, inactive, unknown-user, and successful attempts.
- No database schema change is required.

### Verification
GitHub Actions build and automated tests are required before the feature registry is marked completed and before merge to `main`.
