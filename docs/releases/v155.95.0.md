# v155.95.0

## Setup & Recovery Tool

This release replaces the old first-install-only workflow with a single resilient Windows setup and recovery tool.

### Entry points

- `Install-First-Time.bat` launches `Setup-Tool.ps1`.
- `Install-First-Time.ps1` remains as a compatibility wrapper.
- `Setup-Tool.ps1` is the authoritative implementation.

### Supported operations

- First installation from GitHub.
- Update an existing installation from the configured branch.
- Pull/fetch only.
- Build only.
- Test only.
- Run only.
- Environment/repository diagnostics.
- Push already committed local changes after explicit confirmation.

### Safety and recovery

- No installation path is hard-coded.
- Existing non-Git directories are never overwritten.
- Git `safe.directory` problems are detected and can be repaired after user approval.
- Origin mismatches are detected before synchronization.
- Benign native stderr text is not treated as failure when the native process exits successfully.
- Uncommitted files are detected before update; the user may stash, abort, or explicitly discard.
- Local commits ahead of the remote branch are detected and preserved on a timestamped `setup-backup/*` branch before reset, after user approval.
- Normal update does not run `git clean`.
- Only tracked project `bin` and `obj` directories are cleaned during builds.
- Running `dotnet` processes are never terminated without explicit user approval.
- NuGet restore can clear local caches and retry after approval.
- Port conflicts are reported before application startup when detectable.
- Push mode never creates commits automatically.

### Diagnostics

Every run writes a detailed log under:

```text
%TEMP%\AIWordPressManager-Setup\setup-YYYYMMDD-HHMMSS.log
```

On failure, the setup tool reports the diagnostic log path, last native command, and native exit code.
