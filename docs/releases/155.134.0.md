# Release 155.134.0 — UX-004 Accessibility, Keyboard & Focus Hardening

## Summary

Release `155.134.0` completes UX-004 with a shared accessibility hardening layer focused on WCAG 2.2 AA-oriented keyboard, focus, semantics, motion, contrast and screen-reader behavior.

## Highlights

- Delivered 50 concrete accessibility implementation tasks tracked in `docs/UX_004_50_TASKS.md`.
- Added a shared accessibility runtime that discovers modal dialogs, moves focus into them, traps Tab/Shift+Tab, contains stray focus, restores the opener and locks background scrolling while a modal is active.
- Added a shared polite live region and route-context behavior that focuses `#main-content` and announces the new page title after client-side navigation.
- Corrected shell landmark hierarchy: a real `main` landmark, semantic page `h1`, labelled main region, breadcrumb navigation landmark and `aria-current` page context.
- Hardened the command palette with dialog naming/description, keyboard-shortcut metadata, preferred autofocus, live result updates and generic Escape close integration.
- Hardened `AppDialog` with stable unique IDs, programmatic title/description relationships, configurable close names and focusable dialog containers.
- Hardened `AppButton` with accessible-name fallback, busy state, optional pressed state and disabled-link behavior.
- Hardened `AppSearchBox` with busy announcements, configurable clear naming and autocomplete control.
- Hardened `AppDataGrid` with busy state, named tables, filtered row count, accessible selection labels, pagination landmarks, page-size names and polite page/summary updates.
- Hardened the Accessibility & Display panel with dialog semantics, labelled toggle controls, `aria-pressed`, shortcut metadata, Escape close, trigger-focus restoration and focus preservation after settings updates.
- Added a last-loaded accessibility CSS layer for visible focus, semantic `h1` visual parity, reduced motion, higher contrast, forced colors, non-color selection indication and shared 44px interaction targets.
- Added `AccessibilityContractTests`, including a guard that the UX-004 manifest contains exactly 50 completed tasks.

## Compatibility

- No database migration.
- No domain, persistence, API, authentication, tenant ownership, billing, AI orchestration or WordPress execution behavior changed.
- Existing dark/light and accent themes remain authoritative.
- Existing Arabic RTL and English LTR architecture is preserved; new shared semantics use logical layout behavior.
- Existing `AppDialog`, `AppButton`, `AppSearchBox` and `AppDataGrid` call sites remain source-compatible because all new parameters are optional/defaulted.
