# Release 155.125.0

## AI-006 — Execute approved changes

This release replaces the previous simulated approval-execution path with a real, owner-scoped, version-guarded WordPress content executor.

### Highlights
- Approved changes are no longer marked `Executed` when merely queued.
- New external execution jobs cannot be completed by the Execution Center progress simulator.
- Automatic execution is initially allowlisted to typed WordPress post/page updates with a concrete target and captured `ExpectedModifiedGmt`.
- Content Editor can submit a complete Before/After change for approval.
- Background execution revalidates site ownership and remote WordPress version immediately before mutation.
- Force overwrite is prohibited in approved background execution.
- Crash/retry recovery is idempotent and avoids duplicate POSTs when the desired state is already remote.
- Execution failures remain auditable and retryable without false-success status.
- Generic AI proposals without a concrete WordPress target remain approval-only.
- Executed content changes can generate a new, version-guarded rollback approval; rollback never bypasses review.
- Execution Center exposes approved jobs as managed external mutations and offers safe retry after failure.

### Compatibility
- Existing Execution Center SQLite databases self-upgrade with `ExecutionMode`, `IdempotencyKey`, and `CorrelationId` columns.
- Existing jobs are normalized to `Simulated` mode.
- Existing Approval Workflow persistence is preserved; no destructive migration is required.
- Existing bulk operations retain their previous execution behavior.
