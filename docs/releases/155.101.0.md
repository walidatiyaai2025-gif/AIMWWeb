# 155.101.0 — Bilingual email template foundation

## Scope

Continues Phase 10 with `EML-006` (bilingual reusable email templates).

## Implemented

- Added `IEmailTemplateRenderer` to the Application layer so future outbox/scheduling code does not depend on Razor components.
- Added stable template keys for:
  - site operational report,
  - site SEO summary,
  - site synchronization failure,
  - account/dashboard digest,
  - security alert,
  - billing event.
- Added English and Arabic variants with explicit `ltr` / `rtl` rendering.
- Added HTML and plain-text output for every template.
- Dynamic values are HTML-encoded before insertion into HTML mail bodies.
- Subject values have CR/LF stripped to prevent email-header injection through dynamic template data.
- Required template tokens are validated before rendering; incomplete payloads fail explicitly instead of producing misleading mail.
- Unknown template keys are rejected.
- Added catalog metadata with required and optional tokens so upcoming outbox/schedule UI can discover template requirements.
- Added regression tests for catalog coverage, Arabic/English rendering, HTML encoding, subject newline sanitization, required-token validation, and unknown keys.

## Security notes

- Templates never receive SMTP credentials or protected secrets.
- Dynamic values are treated as untrusted content.
- HTML markup is owned by the application template only; user/site/runtime values are encoded.
- The renderer returns immutable rendered output ready to be snapshotted into the future email outbox.

## Status

`EML-006` is `in_progress` until clean restore/build/tests complete on the Windows development environment. No runtime email-scheduling behavior is claimed in this release.
