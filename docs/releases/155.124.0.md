# AI WordPress Manager 155.124.0

## Tenant-safe approval queue
- Approval records now persist `OwnerUserId` with a backward-compatible SQLite self-migration.
- Approval list, direct read, audit, edit, approve, reject, and immediate execution are owner scoped.
- Legacy ownerless approvals are preserved but are visible only while their `SiteId` belongs to the caller; ownership is never guessed or backfilled.
- New site approvals verify the authoritative current `Site.OwnerUserId` before creation.

## Reviewer and API identity
- Existing approval API routes remain compatible, but workflow authorization is derived from the authenticated `NameIdentifier` claim.
- Reviewer and editor audit identity comes from the authenticated user rather than request-provided display strings.
- Cross-tenant direct IDs return no approval/audit data and cannot be reviewed or edited.

## Execution safety
- Immediate execution creates owner/site-identified Execution Center jobs.
- Approvals cannot be approved or edited after the associated site's ownership changes away from the approval owner.
- Site-less approvals fail closed for immediate execution until a site-scoped execution policy exists.
- Approval idempotency keys are scoped by owner to prevent collisions between tenants while preserving the existing SQLite uniqueness contract.

## UI and AI Center
- `/approvals` reads only the signed-in owner's workflow and shows the authenticated reviewer as read-only identity.
- AI Center submits and refreshes approvals with an explicit current owner, including site-less AI proposals, without relying on ambient `HttpContext` during Blazor events.
