# AIMWWeb 155.151.0 — PayPal subscription lifecycle synchronization

Canonical feature: `BIL-010`
Tracking issue: #150

## Delivered

- Added production PayPal `SubscriptionLookup` capability using authoritative `GET /v1/billing/subscriptions/{id}` snapshots with OAuth bearer authentication and sanitized failures.
- Normalized PayPal pending, active, suspended, cancelled, and expired states without granting authority to browser redirects or checkout results.
- Read provider billing period evidence from `billing_info.last_payment.time` and `next_billing_time` only when both timestamps form a valid UTC range.
- Added write-once provider binding at the account-subscription service boundary. Existing bindings cannot be silently replaced, cleared, or shared by another account subscription.
- Production checkout now persists the PayPal subscription reference only as correlation metadata after server-created checkout succeeds; it never changes subscription status or writes a transition audit.
- Added durable verified-webhook processing state with atomic claims, expired-claim recovery, bounded retry/backoff, replay-safe completion, and sanitized failure metadata.
- Added lifecycle synchronization that resolves accounts only through stored PayPal provider key/reference, reconciles every accepted trigger against a provider API snapshot, and isolates unknown provider references without cross-account mutation.
- Payment-failed triggers retain PastDue until an authoritative snapshot contains a newer successful payment period; explicit suspended/cancelled/expired provider states take precedence.
- Added bounded periodic reconciliation for bound PayPal subscriptions so provider status and renewal drift can be repaired even when a lifecycle webhook is delayed or absent.
- Added SQLite migration `20260818205600_AddPayPalSubscriptionSyncState`; non-SQLite installations continue to use the existing provider-native missing-table upgrade path because BIL-010 adds a new table rather than altering the BIL-009 inbox table.
- Added deterministic regression coverage for PayPal lookup, provider binding immutability/collision isolation, checkout correlation without state mutation, webhook claim/replay behavior, failed-payment recovery, unknown-reference isolation, periodic reconciliation, and SQLite migration.

## Boundaries

No billing UI, plan-change commands, entitlement enforcement, browser callback state mutation, or raw provider payload retention is introduced in this release.

The canonical feature registry is reconciled only after the implementation head passes build and automated tests. The exact final head must pass all required repository gates again before merge.
