# 155.98.0 — Encrypted per-site SMTP profiles

## Scope

Continues Phase 10 with `EML-002` (per-site outbound email profile) and `EML-004` (encrypted email credentials).

## Implemented

- Added `SiteMailProfile` as a tenant-owned, one-profile-per-site domain entity.
- Added EF Core mapping and cascade ownership relation to `Site`.
- Added SQLite compatibility storage for existing SQLite installations.
- Added tenant-safe `SiteMailProfileService`.
- SMTP password is protected through the existing `ISecretProtectionService` before persistence.
- UI never returns or displays the stored SMTP password; it exposes only `HasSavedPassword`.
- Leaving the password field blank preserves the existing encrypted secret.
- Added explicit clear-saved-password operation.
- Added per-site settings for SMTP host, port, username, From address/name, Reply-To, TLS/SSL, and enabled state.
- Added `UseAccountProfile` mode so a site can inherit the dashboard/account mail profile when `EML-003` is implemented.
- Added tests for secret protection/preservation and tenant isolation.

## Not yet claimed complete

- `EML-005` SMTP connectivity diagnostics and test-send are not implemented in this slice.
- `EML-003` dashboard/account mail profile is still pending; choosing inheritance is stored now but delivery falls back only after that profile exists.
- Existing non-SQLite installations still need an explicit schema-upgrade mechanism; fresh non-SQLite databases include the current EF model.
- Clean restore/build/tests and runtime smoke verification are required before changing `EML-002` / `EML-004` to completed.
