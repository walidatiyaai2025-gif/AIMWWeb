# AI WordPress Manager 155.96.0

## First-run database setup

This release introduces a first-run setup flow that keeps the application out of its normal authenticated UI until a database has been configured successfully.

### Supported providers

- SQLite
- Microsoft SQL Server
- PostgreSQL
- MySQL
- MariaDB

The persistence registration selects the EF Core provider from the local setup configuration. SQLite remains the default and recommended option for a single-server installation.

### Setup flow

1. A fresh installation redirects to `/setup`.
2. The user selects a database provider and enters the required connection fields.
3. The application initializes the database schema.
4. For a new database, the user-defined first Administrator account is created.
5. For an existing database, existing application accounts are preserved.
6. Setup is marked complete and the user is redirected to `/login`.

### Existing installations

An existing local SQLite database is detected automatically and bootstrapped into the new setup configuration without forcing the user through first-run setup.

If a previously configured database cannot initialize during startup, the application no longer terminates immediately. Setup is marked incomplete and requests are redirected to `/setup` so the database settings can be corrected.

### Compatibility and safety

- SQLite retains the existing migration path and compatibility schema checks.
- SQLite compatibility now ensures the authentication and login-audit tables required by the current application model.
- New non-SQLite installations are initialized from the complete current EF model rather than replaying SQLite-specific legacy migrations.
- The automation scheduler does not execute WordPress jobs until database setup is complete.
- Existing users and site ownership are preserved during database recovery.
- A custom first Administrator prevents creation of an additional default Admin account on subsequent starts.
- Database setup configuration is stored locally on the machine and is not committed to Git.

## Validation focus

Recommended validation scenarios:

- Fresh SQLite installation.
- Existing SQLite installation upgraded from an earlier release.
- Fresh SQL Server installation.
- Fresh PostgreSQL installation.
- Fresh MySQL/MariaDB installation.
- Invalid database credentials followed by a corrected retry.
- Configured database unavailable during application startup, followed by setup recovery.
- Existing database with existing application accounts.
