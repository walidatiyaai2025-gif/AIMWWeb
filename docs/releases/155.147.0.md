# AIMWWeb 155.147.0 — Provider-neutral payment gateway abstraction

Canonical feature: `BIL-006`
Tracking issue: #142

## Delivered

- Added `IPaymentGateway` and `IPaymentGatewayRegistry` as the provider-neutral boundary for future subscription checkout, verified inbound events, subscription reconciliation, cancellation/reactivation and plan changes.
- Added stable normalized gateway identity and explicit capability flags so callers can reject unsupported operations before invoking a provider adapter.
- Added normalized external subscription states without coupling application business logic to a provider SDK or provider-specific type system.
- Added explicit evidence authority: checkout/session results are `NavigationOnly`; only verified gateway events and provider API snapshots are authoritative external evidence inputs.
- Added validated contracts for server-created checkout navigation, webhook envelopes/results, verified events, provider subscription snapshots, command requests and plan-change requests.
- Added deterministic case-insensitive gateway registry resolution, stable ordering, duplicate-key rejection and explicit missing/capability errors.
- Registered the empty-safe gateway registry through Infrastructure DI; concrete provider adapters remain future registrations.
- Added automated tests for normalization, registry routing, duplicate protection, capability checks, authority boundaries and validation of identifiers, URLs, UTC timestamps and period chronology.

## Boundaries

- No provider SDK, HTTP client, credentials, configuration, endpoint, persistence or provider-specific implementation is introduced.
- No browser return/navigation payload can represent payment or subscription success.
- No PayPal-specific name/type appears in the application payment-gateway contract.
