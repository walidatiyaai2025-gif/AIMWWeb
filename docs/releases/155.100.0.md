# 155.100.0 — SMTP diagnostics and test email

## Scope

Continues Phase 10 with `EML-005`: actionable SMTP diagnostics and test email for account and site mail profiles.

## Implemented

- Added shared `SmtpDiagnosticsService`.
- DNS resolution check with sanitized failure output.
- TCP reachability check for the configured SMTP host/port with timeout handling.
- Test email submission using the saved encrypted SMTP profile.
- TLS/authentication/SMTP failures are mapped to actionable messages without exposing passwords or protected secrets.
- Added reusable `SmtpDiagnosticsPanel` for account/site flows.
- Added diagnostics to `/account/email-settings`.
- Added site diagnostics workspace at `/sites/{siteId}/email-diagnostics`.
- Added direct SMTP diagnostics link from Site Settings.
- Test profiles can be diagnosed before outbound sending is enabled; production delivery still respects `IsEnabled`.
- Site profiles configured with `UseAccountProfile` diagnose the inherited account SMTP profile.
- Updated the email/billing feature registry: Phase 10 and `EML-001` through `EML-005` are now `in_progress` instead of stale `planned` values.

## Security behavior

- Stored SMTP passwords are never returned to Razor forms.
- Passwords are decrypted only inside delivery/test profile creation.
- Diagnostic output never includes username/password pairs, protected values, or raw exception text from SMTP providers.

## Interpretation

- A successful **Diagnose connection** confirms DNS resolution and TCP connectivity only.
- A successful **Send test email** confirms that the SMTP server accepted the message using the configured TLS/authentication path.
- Inbox delivery is not guaranteed by this test because provider filtering, spam policy, forwarding, and downstream delivery are outside the application.
