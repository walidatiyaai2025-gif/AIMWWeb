# Release 155.130.0

## AI-007 — Tenant-safe persistent AI usage and cost observability

This release completes the AI usage/cost work by turning process-local telemetry into durable, account-scoped observability with a bilingual dashboard.

### Highlights
- Production `IAIUsageLog` now persists to the managed application `Data/ai-usage-log.json` path and reloads across restarts.
- The usage file is written atomically, retains the latest 10,000 entries, and quarantines corrupt storage before recovering with a clean log.
- Telemetry persistence is non-fatal: an I/O failure cannot turn a successful provider response into a failed AI request.
- Usage entries normalize provider/model/operation/error metadata, negative token counts, negative estimated cost, UTC timestamps, and user identifiers.
- `/api/ai/usage` no longer accepts an arbitrary `userId`; records are scoped to the authenticated account by `AIUsageWebService`.
- Optional usage site filters are validated against the authenticated user’s owned WordPress sites.
- `/api/ai/generate`, AI Center, and Planner AI generation now attribute usage to the server-resolved authenticated user rather than trusting a client-supplied identity.
- AI Center’s recent-usage counter is account-scoped.
- Added bilingual `/module/ai-usage` dashboard with total calls, success rate, input/output tokens, adapter-reported estimated cost, provider and operation breakdowns, owned-site filtering, and recent success/failure activity.

### Privacy and security boundary
- Usage telemetry does not persist prompt contents or provider secrets.
- Legacy request `UserId` fields remain accepted for wire compatibility but are ignored by the server-owned attribution paths covered by this release.
- Provider adapters remain authoritative for `EstimatedCost`; zero remains zero when an adapter does not provide a pricing estimate.

### Compatibility
- No database migration.
- Existing `IAIUsageLog` and `AIUsageEntry` contracts remain compatible.
- Existing AI provider orchestration and AI-003 prompt storage remain unchanged.

### Regression coverage
Automated tests cover:
- persistence and reload after restart,
- per-user tenant filtering,
- user + site filter interaction,
- bounded retention keeping only the newest records,
- corrupt-file quarantine and recovery,
- normalization of timestamps, IDs, negative counters, and metadata.
