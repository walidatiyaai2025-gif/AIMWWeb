# 155.140.0 — Non-SQLite schema upgrade compatibility

## Summary

Existing SQL Server, PostgreSQL, MySQL, and MariaDB installations can now add tables introduced by newer application versions without replaying the repository's SQLite-shaped historical migrations or recreating existing tables.

## Implemented

- Keep SQLite on its existing `MigrateAsync` plus compatibility path.
- After `EnsureCreatedAsync` on supported non-SQLite providers, inspect the live schema for current tables.
- Generate the full create script from the active EF Core provider so DDL types and identifier quoting remain provider-native.
- Execute only `CREATE TABLE`, `CREATE INDEX`, and relevant `ALTER TABLE` commands that target tables missing from the live database.
- Preserve existing tables and data; a current schema produces an idempotent no-op.
- Patch and backfill the legacy `EmailOutboxMessages.Scope` discriminator for SQL Server, PostgreSQL, MySQL, and MariaDB when needed.
- Add regression tests covering SQL Server batch separators/bracket identifiers, PostgreSQL quoted identifiers and ALTER ordering, MySQL backticks, schema-qualified identifiers, and idempotent behavior.
