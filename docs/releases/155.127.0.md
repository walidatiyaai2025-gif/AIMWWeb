# Release 155.127.0

## AI-002 — AI provider configuration

This release turns the existing AI settings foundation into a secure, administrator-managed runtime configuration path for the application AI providers.

### Highlights
- Added a bilingual administrator-only AI provider settings workspace at `/settings/ai-providers`.
- Global AI enablement and automatic provider fallback are configurable from the application settings store.
- Provider enabled state, priority, and model are now enforced by the production AI runtime.
- OpenAI, Gemini, and Puter production adapters consume the persisted provider configuration.
- Existing server configuration remains a compatibility fallback when no encrypted database credential is stored.
- Puter keeps its endpoint as a server-side setting and requires an absolute HTTPS endpoint; its token is optional.
- Groq, OpenRouter, and Ollama configuration can be retained in the shared settings model without falsely claiming a production adapter in this release.

### Secret handling
- Reuses the existing AES-GCM `ISecretProtectionService`; no plaintext API key is persisted.
- Saved keys are never returned to the UI as plaintext.
- Leaving a credential input blank preserves the currently stored credential.
- Administrators can explicitly remove a saved provider credential.
- Legacy OpenAI protected-key storage remains readable and is removed together with the current key when explicitly cleared.
- Provider HTTP failures expose sanitized status information rather than response bodies that could contain sensitive data.

### Regression coverage
- New credentials are protected before persistence and can be decrypted only through the application settings service.
- Blank credential updates preserve an existing key.
- Explicit removal deletes the stored credential without silently disabling the provider.
- Runtime provider ordering follows persisted priority.
- Disabling automatic fallback prevents the next provider from being attempted.
- Enabling fallback allows the next enabled provider to serve the request.
