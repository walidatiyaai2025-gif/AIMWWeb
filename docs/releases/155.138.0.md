# Release 155.138.0 — UX-008 RTL/LTR Visual Parity

## Summary

Release `155.138.0` completes UX-008 with exactly 100 tracked code tasks focused on Arabic RTL / English LTR parity without duplicating application layouts.

## Shared direction and bidi system

- Added `AppBidiText` using semantic bidi isolation for mixed-language technical, numeric, date, time, version, path, URL and email values.
- Added `AppDirectionalIcon` and extended `AppButton` with source-compatible directional icon intent and optional RTL mirroring.
- Extended `AppBadge` with optional bidi mode and `AppDialog` with an optional direction scope while preserving existing call sites.
- Added a pre-paint language bootstrap so a saved Arabic preference applies RTL before styles render, avoiding LTR-to-RTL first-paint movement.
- Added `bidi-runtime.js` and synchronized `lang`, `dir`, `data-app-language` and `data-app-direction` metadata on the document root and body.

## Logical layout parity

- Added final-layer `rtl-ltr-parity.css` using logical inline properties for shell, navigation, breadcrumbs, popovers, forms, dialogs, data grids, bulk actions, feedback surfaces and technical metadata.
- Spatial breadcrumb/paging/button icon behavior mirrors in RTL while neutral icons remain unchanged.
- Technical and numeric values are isolated LTR without forcing surrounding Arabic content out of RTL reading order.
- Responsive safe-area behavior, mobile action stacking, reduced-motion and forced-colors behavior are covered without introducing a second Arabic layout tree.

## Production adoption

- Build & Release Notes now isolates version, branch, commit, dates, assembly metadata and API/file paths so mixed Arabic/technical content remains readable and stable.
- The copied build-report payload is intentionally unchanged; UX-008 changes presentation only.
