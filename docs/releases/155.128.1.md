# Release 155.128.1

## AI-003 runtime hardening — prompt discovery and availability guards

This patch preserves the AI-003 `VersionedAIPromptRegistry` architecture shipped in `155.128.0` and fixes two runtime integration defects discovered during post-merge review.

### Fixed
- AI Center now enumerates the enabled prompt dictionary directly instead of serializing a dictionary and attempting to parse it as a JSON array.
- The AI Center prompt library therefore exposes the enabled runtime templates as intended.
- Added safe `IAIPromptRegistry.TryGet` lookup semantics based on the enabled runtime catalog.
- AI Center rejects unknown or disabled prompt keys before calling the AI orchestrator.
- `/api/ai/generate` returns `400 Bad Request` for unknown or disabled prompt keys instead of sending an invalid/empty system prompt to an AI provider.
- Existing custom `SystemPrompt` behavior is preserved when no `PromptKey` is supplied.

### Compatibility
- No prompt storage format change.
- No database migration.
- No change to the accepted atomic JSON persistence, quarantine/recovery, idempotent saves, revision history, or administrator management workflow from `155.128.0`.
- Existing `IAIPromptRegistry` implementations remain source-compatible because `TryGet` is a default interface method.

### Regression coverage
`AIPromptRegistryVersioningTests.Safe_Runtime_Lookup_Rejects_Disabled_And_Unknown_Keys` verifies that:
- enabled templates resolve successfully,
- disabled templates are rejected and return no prompt text,
- unknown keys are rejected and return no prompt text.
