# 155.141.0 — Durable WordPress sync-failure email alerts

## Summary

Persisted WordPress synchronization failures can now be relayed to the affected site's configured notification recipients through the existing durable email outbox. Alert generation is decoupled from the original synchronization exception path so email problems cannot mask or replace the WordPress failure.

## Implemented

- Add a background-safe operational alert service that accepts explicit `OwnerUserId` and `SiteId` rather than relying on HTTP current-user state.
- Resolve only enabled notification recipients belonging to the same owner and site.
- Render the existing bilingual `site.sync-failure` template; sites whose WordPress language begins with `ar` receive Arabic output, otherwise English is used.
- Route alerts exclusively through `IEmailOutbox`; no direct SMTP send path was introduced.
- Use the persisted `SiteSyncRun.Id` to derive deterministic idempotency and correlation identities, preventing duplicate alerts across relay retries and process restarts.
- Sanitize password/token/API-key/authorization assignments, bearer credentials and URL user-info; collapse line breaks and bound failure details before they are copied into an email/outbox snapshot.
- Add a hosted relay worker that scans recent persisted failed synchronization runs with a 24-hour recovery window. Per-event failures remain retryable and do not affect WordPress synchronization.
- Add regression coverage for tenant isolation, enabled/disabled recipients, no-recipient behavior, idempotency, secret redaction, Arabic rendering, persisted failed-run relay and successful-run exclusion.
