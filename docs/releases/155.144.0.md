# AIMWWeb 155.144.0 — Typed plan entitlement engine

Canonical feature: `BIL-002`
Tracking issue: #136

## Delivered

- Added a durable `PlanEntitlement` domain model keyed by internal plan identity plus stable entitlement key; entitlement identity cannot be changed after creation.
- Added the approved initial entitlement definitions: `sites.max`, `email.siteRecipients.max`, `email.schedules.max`, `email.dashboardDigest`, `automation.schedules.max`, `ai.enabled`, `ai.monthlyRequests.max`, `backup.retentionDays`, and `premium.seo`.
- Added invariant typed value support for Boolean, Integer, Decimal, and String values. Initial numeric max/retention definitions reject negative values and no unlimited sentinel is invented.
- Added `IPlanEntitlementCatalog` for definition discovery, plan-scoped list/set/remove operations, and `IPlanEntitlementResolver` for explicit typed resolution, Boolean capability checks, and reusable integer-limit checks.
- Missing entitlements remain explicit (`IsConfigured=false`) and do not silently grant a capability or invent a numeric limit.
- Added EF Core persistence with unique `(PlanId, NormalizedKey)`, plan foreign key/cascade deletion, database duplicate-race protection, SQLite migration `20260818184500_AddPlanEntitlements`, and DI registration.
- Existing SQL Server/PostgreSQL/MySQL/MariaDB installations continue to use provider-generated DDL plus the existing missing-table upgrade planner.
- Added deterministic coverage for canonical definitions, typed codec behavior, missing/fail-closed resolution, upsert/remove, plan isolation, integer-limit checks, unknown/type-mismatch rejection, plan FK behavior, database uniqueness, and SQLite migration creation.

## Boundaries

- No account subscription binding is introduced; `BIL-003` owns subscription state and plan assignment.
- No product-module entitlement enforcement is introduced; `BIL-012` owns integration across sites, email, automation, AI, SEO and other product services.
- No PayPal or gateway-specific dependency is introduced.
- No commercial entitlement values are seeded.

Final merge remains conditional on the exact PR head passing Build, .NET Build Verification, UX Regression Gate, and PR Plan Link with zero unresolved review threads.
