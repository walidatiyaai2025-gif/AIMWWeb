# AI WordPress Manager v155.96.5

Security and reliability follow-up for encrypted application/database credentials.

## Fixed

- The AES-GCM secret key is no longer stored under build output where `bin/Debug` or `bin/Release` cleanup can delete it.
- The key is now stored in the stable per-user application data directory under `AIWordPressManager/Security`.
- Existing legacy `.secret-key` files are migrated automatically when present.
- Previously encrypted WordPress and database credentials remain readable after a clean/rebuild when the legacy key still exists.
- Key writes use a temporary file plus atomic replace to reduce partial-write risk.

## Validation focus

1. Encrypt a credential, clean `bin`/`obj`, rebuild, and verify it can still be decrypted.
2. Upgrade an existing installation with a legacy `Data/.secret-key` and confirm the key is migrated.
3. Restart after first-run setup with SQL Server/PostgreSQL/MySQL/MariaDB.
