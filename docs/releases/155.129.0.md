# Release 155.129.0

## AI-004 — Structured AI suggestions with reviewable evidence

This release turns AI Center output from an opaque text blob into a structured, reviewable proposal that carries evidence through the existing approval workflow.

### Highlights
- Added an `AISuggestion` contract with authoritative `Before`, proposed `After`, `Explanation`, `Confidence`, and `AffectedFields`.
- AI Center layers a strict JSON response contract over the selected AI-003 prompt template.
- The parser fails closed when a provider returns malformed JSON, missing required values, invalid confidence, empty affected fields, oversized content, or excessive field identifiers.
- The original `Before` value always comes from the application. Any AI-supplied source value is ignored, preventing the provider from rewriting the evidence being reviewed.
- AI Center now renders the proposal, rationale, confidence, affected-field badges, and Before/After comparison in the bilingual workspace.
- Session history retains and restores the complete structured suggestion.
- Approval submissions preserve explanation, confidence, and affected fields in the existing `BeforeJson` / `AfterJson` evidence instead of creating a separate approval data path.

### Compatibility
- No database migration.
- No change to AI-003 prompt persistence or prompt-version history.
- No parallel approval store.
- No change to AI-005/AI-006 approval or WordPress execution policy.
- Existing approval persistence continues to serialize the richer evidence payload into the established JSON columns.

### Regression coverage
Automated tests cover:
- valid structured suggestions,
- Markdown-fenced JSON returned by a provider,
- preservation of the application-owned original value,
- case-insensitive affected-field deduplication,
- malformed/incomplete JSON,
- invalid confidence values,
- empty affected-field lists,
- Arabic structured-output instructions.
