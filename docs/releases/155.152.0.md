# AIMWWeb 155.152.0 — Account subscription and billing workspace

Canonical feature: `BIL-005`
Tracking issue: #152

## Delivered

- Added a bilingual authenticated `/account/billing` workspace for current subscription, localized plan identity, status, lifecycle dates, next relevant date, cancel-at-period-end/grace context, and a masked external-provider binding summary.
- Added an owner-scoped Web service boundary that composes BIL-002 plan entitlements, BIL-003 subscription state/transition history, BIL-001 plan catalog data, and BIL-008 PayPal checkout without embedding provider/business rules in Razor.
- Checkout eligibility is revalidated server-side and blocks missing subscriptions, expired records, unavailable/disabled plans, missing PayPal plan mapping, and already-bound provider subscriptions.
- PayPal checkout remains navigation-only: browser return/cancel routes never mark payment success or change subscription state; verified webhook/provider reconciliation remains authoritative through BIL-009/BIL-010.
- Provider references shown to customers are masked; raw provider payloads, tokens, credentials, and secret configuration are never surfaced by the workspace.
- Added truthful configured-entitlement display without inventing usage counters that BIL-002 does not provide. Server-side feature/usage enforcement remains owned by BIL-012.
- Added enabled plan catalog visibility while leaving upgrade/downgrade/cancel/reactivate mutations to BIL-011 and broader billing-event/customer-notification history to BIL-013.
- Added System & Account navigation plus bilingual quick-search metadata for the billing workspace.
- Added responsive page-specific CSS, RTL handling, loading/error/empty states, accessibility labels, and registered the route as high-risk UX coverage across phone, tablet, desktop, authenticated, and RTL gates.
- Added deterministic service and navigation regression coverage for tenant ownership, provider-reference masking, checkout blocking, deterministic correlation, no subscription-state mutation from UI checkout, and route/search discoverability.

## Boundaries

No plan-change commands, cancel/reactivate mutation flow, usage-counter invention, manual payment success, raw provider data, billing notification history, or product-module entitlement enforcement is introduced in this release.

The canonical feature registry is reconciled only after the implementation head passes build and automated tests. The exact final head must pass all required repository gates again before merge.
