# AI WordPress Manager 155.122.0

## Multi-tenant execution traceability
- Execution Center jobs now persist application owner and site identities.
- Existing execution-center SQLite databases are upgraded in place without assigning fabricated owners to legacy jobs.
- Job/activity reads and pause/resume/retry/cancel actions are tenant scoped.
- Dashboard and Execution Center no longer infer ownership from site display names.

## Operation history
- Site-operation records can persist owner identity and linked Execution Job ID.
- Synchronization history now correlates directly with its Execution Center job.
- Direct operation-detail routes, reliability views, hub/overview pages, diagnostics export, and cleanup maintenance are scoped to the signed-in owner's sites.
- Legacy ownerless JSON history remains available only when its exact SiteId is currently owned by the user.

## Safety
- Tenant cleanup cannot delete another owner's history.
- Unidentified legacy execution jobs are hidden from tenant views instead of being attributed by name.
- Approval workflow tenant ownership remains a separate tracked acceptance item.

## Verification
- Added migration, isolation, lifecycle authorization, history correlation, legacy compatibility, and cleanup-isolation tests.
- Full solution build and automated tests are required before merge.
