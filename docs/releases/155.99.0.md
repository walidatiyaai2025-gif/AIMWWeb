# 155.99.0 — Dashboard/account email settings

## Scope

Continues Phase 10 with `EML-003`: account/dashboard recipients and an account-level outbound mail profile used by sites configured with `UseAccountProfile`.

## Implemented

- Added `AccountEmailRecipient` and `AccountMailProfile` to the active EF model.
- Added account-level recipient isolation by authenticated user.
- Supports up to three dashboard recipients per account with case-insensitive duplicate prevention.
- Added encrypted account SMTP password storage using the existing `ISecretProtectionService`.
- Stored SMTP passwords are never returned to the UI; only `HasSavedPassword` is exposed.
- Blank password updates preserve the existing encrypted secret.
- Added explicit clear-saved-password operation.
- Added `/account/email-settings` with SMTP host, port, username, From, Reply-To, TLS/SSL, enabled state, and dashboard recipient management.
- Linked the new workspace from `/account/profile`.
- Existing SQLite installations now create `AccountEmailRecipients` and `AccountMailProfiles` compatibility tables/indexes during initialization.
- Site `UseAccountProfile` delivery resolution now reads the account mail profile and decrypts the secret only when a delivery profile is requested.
- Added tests for recipient limits, duplicate prevention, account isolation, SMTP secret protection/preservation, and site-to-account profile inheritance.

## Build stability note

The four email entities referenced by `AppDbContext` are present on `main` and the Domain project uses default SDK compile inclusion. A local Visual Studio checkout showing `CS0246` for these entities is stale/incomplete and must be synchronized to current `origin/main` before evaluating the current build.
