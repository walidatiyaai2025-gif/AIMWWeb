# 155.112.0 - Public Root and Login Continuation

- Anonymous `GET /` and `HEAD /` now enter the public `/welcome` landing experience instead of being challenged for authentication.
- Authenticated `/` requests continue to use the existing dashboard route.
- Successful first-time database setup now opens `/welcome`, so the product overview is the first post-setup experience.
- Visiting `/setup` after setup is complete also returns to `/welcome`.
- Public landing CTAs now preserve a safe local `returnUrl` through the login form and resume the intended protected destination after successful sign-in.
- First-run users without sites still default to `/welcome` when they sign in directly, but an explicit safe CTA target such as `/sites/connect` is honored.
- Unsafe external return URLs remain rejected by `LocalAuthenticationService.ResolveRedirectPath`.
- Login errors are shown on the login form without dropping the safe continuation target.
- Logout now returns to the public product landing.
