# AI WordPress Manager v155.96.11

Maintenance release aligning configuration diagnostics with the first-run database setup architecture.

## Fixed

- Configuration Validation now uses `IApplicationPathService` instead of hard-coded Production storage paths.
- Development and Portable storage checks now validate the same directories the application actually uses.
- The database check now reads `Database:Provider` and `Database:SetupComplete` instead of legacy `ConnectionStrings:*` keys.
- SQL Server, PostgreSQL, MySQL, MariaDB, and SQLite are validated through the current setup model.
- Server-database credentials are never shown in the validation report; only provider/readiness state is displayed.
- Legacy plain connection strings remain recognized for backward compatibility without being rendered to the UI or copied report.

## Validation focus

1. Open `/module/configuration` after a successful SQLite setup.
2. Repeat with a server database provider and confirm only the provider name is shown.
3. Verify Development paths point under `%LOCALAPPDATA%\AIWordPressManager\Development`.
4. Verify the copied report contains no passwords, connection strings, or encrypted credential payloads.
