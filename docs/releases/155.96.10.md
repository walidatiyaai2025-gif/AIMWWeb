# AI WordPress Manager v155.96.10

Maintenance release for environment-safe automation storage.

## Fixed

- `AutomationCenterService` now stores `automation-center.db` through `IApplicationPathService` instead of a hard-coded Production LocalAppData path.
- Development automation data now follows `%LOCALAPPDATA%\AIWordPressManager\Development\Data`.
- Portable mode keeps automation data beside the application, consistent with the rest of the application storage model.
- Existing automation jobs from the historical LocalAppData path are copied forward on first use when the corrected target database does not already exist.
- Migration failures caused by a locked or protected legacy automation database no longer block application startup.

## Validation focus

1. Start in Release/Production and confirm existing automation jobs remain visible.
2. Start in Debug/Development and confirm `automation-center.db` is created under the Development data root.
3. Verify Portable Mode keeps the automation database under the portable Data directory.
4. Verify scheduled jobs remain gated until `Database:SetupComplete=true`.
