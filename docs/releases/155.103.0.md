# AI WordPress Manager v155.103.0

## Scope

Phase 2 identity hardening (`IDN-010`) plus a narrow compatibility fix for the active email outbox worker introduced in v155.102.0.

## IDN-010 — Account lockout and failed sign-in tracking

- Retains the five-failed-attempt threshold and fifteen-minute lockout window.
- Adds an explicit domain lockout-state check.
- Clears expired lockout state before counting a subsequent failed attempt, so one failure after expiry starts a fresh attempt window instead of immediately extending the previous lock.
- Preserves successful-login reset behavior and existing login audit records.
- Adds automated coverage for active lockout, exact expiry, post-expiry failures, and successful recovery.

## Email outbox compatibility fix

The v155.102.0 claim path uses EF Core `ExecuteUpdateAsync`, which intentionally bypasses the local change tracker. If the same scoped `DbContext` still tracks the message from enqueue, a later sent/failed transition can observe the stale pre-claim entity.

- Before validating a claimed message for sent/failed transition, only the matching tracked `EmailOutboxMessage` is detached so current database state is loaded.
- The new multi-instance-safe stale-claim recovery from v155.102.0 is preserved unchanged.
- Tenant scope, retry, idempotency, SMTP resolution, and delivery-attempt history remain unchanged.

## Validation

A clean GitHub Actions build and complete automated test run are required before `IDN-010` is marked completed.

No database schema change is required.
