# AI WordPress Manager v155.106.0

## Scope

Phase 10 email scheduling: `EML-007` per-site scheduled reports and `EML-008` account/dashboard digest schedules.

## Delivered

- Durable `EmailSchedule` records scoped explicitly to the owning application user and optionally to one owned WordPress site.
- Hourly, daily, weekly, and monthly recurrence with persisted timezone ID and local delivery time.
- Timezone-safe next-run calculation with daylight-saving invalid-time normalization and deterministic handling of ambiguous local times.
- English/Arabic template preference persisted per schedule.
- Per-site operational report schedules using enabled site recipients.
- Account/dashboard digest schedules using enabled dashboard recipients.
- All scheduled messages are rendered and persisted through `IEmailOutbox`; the scheduler never sends SMTP directly.
- Idempotency keys are based on schedule ID plus the logical scheduled occurrence, preventing duplicate messages when a worker retries or restarts.
- Atomic schedule claims plus stale-claim recovery protect against duplicate processing across overlapping worker loops or multiple web instances.
- Separate preparation retry policy with persisted retry count/delay and stable logical occurrence IDs.
- Background `EmailScheduleWorker` gated by first-run database setup completion.
- Unified `/email/schedules` bilingual workspace with account/site scope, timezone, recurrence, language, retry settings, next run and last status.
- Navigation from site email settings and account email settings.
- Automated coverage for next-run calculation, end-of-month behavior, bilingual account scheduling, and cross-tenant site isolation.
- SQLite migration for the scheduling table and persisted scheduler state.

## Current initial report scope

- Site schedules currently produce the `site.operational-report` template.
- Account schedules currently produce the `account.dashboard-digest` template.
- Additional site report types can be enabled behind the same scheduler/outbox contract in later Phase 10 work.

## Safety and reliability

- Background execution carries `OwnerUserId` explicitly and never depends on an interactive `CurrentUserContext`.
- A site schedule cannot be created for a site owned by another account.
- Recipient snapshots are produced at enqueue time by the durable outbox.
- Schedule preparation failures are sanitized and retried without exposing SMTP secrets.
- SMTP delivery retries remain the responsibility of the outbox worker, separate from schedule preparation retries.

## Validation still required

A clean local restore/build/test run and runtime verification against the configured database/SMTP provider are required before `EML-007` or `EML-008` is marked completed. Existing non-SQLite installations still require the broader explicit schema-upgrade path tracked by the database-provider work.
