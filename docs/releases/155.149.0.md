# AIMWWeb 155.149.0 — Server-created PayPal subscription checkout

Canonical feature: `BIL-008`
Tracking issue: #146

## Delivered

- Added a concrete PayPal `IPaymentGateway` adapter advertising only `SubscriptionCheckout` in this release.
- Checkout obtains an OAuth access token in memory, calls the selected sandbox/live `/v1/billing/subscriptions` endpoint, and sends the internal PayPal plan mapping plus validated return/cancel URLs.
- Added deterministic `PayPal-Request-Id` generation from the internal checkout correlation so retries reuse the same provider idempotency key.
- Added strict success parsing for PayPal subscription ID and HTTPS approval link under `paypal.com`.
- Checkout results remain `NavigationOnly`; provider status, approval URL and browser return data never mutate the internal subscription state.
- Added server-side checkout orchestration that resolves the account subscription and stored plan mapping from the database, rejects wrong-owner, disabled, unmapped or terminal subscription inputs, then delegates to the payment gateway registry.
- Added sanitized OAuth/checkout failures that do not expose provider response bodies, access tokens or client secrets.
- Added Infrastructure and Persistence DI registration for the PayPal checkout gateway and orchestration service.
- Added automated tests for sandbox/live routing, OAuth/Bearer request shape, deterministic idempotency header, checkout body, navigation-only result, server-owned plan mapping, state non-mutation, malformed/untrusted responses and sanitized failures.

## Boundaries

No webhook processing, subscription reconciliation, browser callback state mutation, plan-change flow, billing UI, or new database schema is introduced.

Final merge remains conditional on the exact PR head passing all required repository gates with zero unresolved review threads.
